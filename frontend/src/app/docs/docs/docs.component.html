Confirmations, InstantSend, and ChainLocks

A confirmation means the transaction is included in a block. Dash targets roughly one block every 2.5 minutes; actual intervals vary. The explorer’s pending list is an observed notification sample, so it does not estimate a confirmation time.

InstantSend is a Dash protocol that can lock eligible transactions through quorum consensus before block confirmation. ChainLocks are quorum signatures for blocks that protect the accepted chain against reorganizations. These are protocol concepts: this public API does not expose an authoritative InstantSend or ChainLock status endpoint. Where a transaction page shows an InstantSend label, it is a provider observation, not a substitute for wallet verification.

Data coverage and limits

Blocks, transactions, address balances, and indexed history come from the Dash Insight service. Address history is cursor-paginated in pages of 25. Transaction values and fees are integer duffs; fees are byte-based because Dash does not use a SegWit weight discount.

The pending panel only includes transactions observed from the provider notification stream after this explorer connected. It is intentionally not represented as the network-wide mempool. Fiat values are current USD observations, not historical prices. Provider failures return 503; a missing entity returns 404.

Dash special transactions

Dash Core supports special transactions, including masternode and quorum-related records and Platform withdrawals. A Platform withdrawal can carry its fee in the special payload, so calculating input value minus output value is not reliable for every special transaction. This explorer reads the documented payload fee when it is available and otherwise leaves the fee unavailable.

Protocol references

Dash Core features describes InstantSend and ChainLocks. Dash Core transaction reference covers transaction formats and special transaction data.

REST API

The API is available on the same origin at https://dash.tx.taxi/api. It is read-only: it does not broadcast transactions, accept packages, or provide Electrum, Lightning, RBF, or enterprise endpoints.

Responses include X-DASH-Source, X-DASH-Observed-At, and X-DASH-Stale headers. Treat an observation timestamp as freshness information, not a blockchain timestamp.

Blocks

Get the current tip

GET /api/blocks/tip/height
curl https://dash.tx.taxi/api/blocks/tip/height

Get a block hash from a height

GET /api/block-height/:height
curl https://dash.tx.taxi/api/block-height/100000

Get block data and transactions

GET /api/v1/block/:hash
GET /api/block/:hash/txs/:startIndex

Use /api/block/:hash/txids for transaction IDs and /api/v1/block/:hash/summary for a bounded complete summary. A summary above 500 transactions reports unavailable instead of returning a partial result as complete.

curl https://dash.tx.taxi/api/v1/block/00000000000fd08c2fb661d2fcb0d49abb3a91e5f27082ce64feed3b4dede2e2

Transactions

Get a transaction

GET /api/tx/:txid

Values, fees, and output amounts are integer duffs. Optional suffixes are /status, /hex, and /outspends.

curl https://dash.tx.taxi/api/tx/836f0f697b6d3a6283c7c264a5a144c893e7b077ef4aea87dbb4f32d81ac86c5

Get outspends for several transactions

GET /api/txs/outspends?txids=:commaSeparatedTxids

The gateway accepts at most 25 transaction IDs in this batch.

Addresses and indexed history

Get an address summary

GET /api/address/:address

The returned confirmed and unconfirmed totals are in duffs. UTXO counts are unavailable from this provider and are returned as null.

curl https://dash.tx.taxi/api/address/XrgrCXZFhLNfyR4UKv9YT19CK7YVEPrc8Y

Page through address transactions

GET /api/address/:address/txs
GET /api/address/:address/txs/chain/:lastTxid

Each page has up to 25 indexed transactions. A cursor that has expired or no longer matches provider history is an error, rather than silently restarting at the first page.

Observed live data

Recent notification sample

GET /api/mempool/recent

Returns up to 100 pending transactions observed since the latest notification connection. It returns 503 while the provider notification stream is unavailable.

Snapshots, prices, and health

GET /api/v1/init-data
GET /api/v1/prices
GET /api/provider-health

Prices are current USD observations. Health describes gateway and provider freshness; it does not attest to transaction finality. The service does not provide a recommended-fee endpoint; use the observed transaction fee rates shown in the explorer without treating them as a confirmation forecast.

WebSocket stream

Connect to wss://dash.tx.taxi/api/v1/ws. The explorer uses this stream for a bounded initial snapshot and subsequent Dash provider observations. It is not a general Dash Core RPC socket.

Connect

const socket = new WebSocket('wss://dash.tx.taxi/api/v1/ws');

socket.onmessage = event => console.log(event.data);

Reconnect with backoff after a close. A connection may initially report a snapshot or reconnecting state while upstream notifications are unavailable.

What the stream can contain

Messages may include the initial block snapshot, refreshed block data, observed pending transactions, and connection state. Observed pending transactions are bounded and are removed when later observations show them confirmed.

Do not derive a global mempool count, projected block template, InstantSend state, or ChainLock state from this stream.
